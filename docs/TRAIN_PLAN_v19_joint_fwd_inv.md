# v19 训练计划：对齐后数据的正逆联合训练（草案，待 Codex 审核）

> 状态：草案，未开始训练。本文只定计划与验收标准，不改任何权重、不跑任何训练。
> 背景文件：`docs/LOG_2026-10-22_M208_channel_delay.md`（42 ms 错位定案）。
> 参考文献：PDIA《Physics-driven invertible architecture for unified forward-inverse
> modeling of magnetorheological dampers》，Nonlinear Dynamics，
> DOI 10.1007/s11071-026-13039-w（v7 起“双 observer”思想的出处）。

## 1. 结论先说：能一起训，但不能照搬 v18

- **能**：正逆联合训练在架构上是可行的，前提是改掉 v18 的三个错误口径
  （见 §2），并用分阶段 + 门禁代替“一把梭”的联合 loss。
- **不能照搬 v18**：v18（`AA02Train/train_v18.py`，NLCSNN_v14 骨架，
  GRU 64 / MLP 128 / G 64，138,512 参数）从 v17 E480 热启动后，
  会话 `v18_20261015_221237` 最优 E501：pooled NRMSE **36.24%**、
  inv_mae **0.464 A**、loss_fwd 0.0273。相对 v17（E480 pooled 16.27%）
  正向反而变差约一个量级，逆头也没学出来。联合训练本身不是失败原因，
  是 loss 设计 + 评估口径 + 模型规模三处同时错了。
- **保底路线（一定能交付）**：Stage 1 正向模型 + v17 已验证的解析逆解
  （单调 G 二分 / 9 点网格，MATLAB 端 F_ach 与 plant F 已验证重合）。
  神经逆头是增强项，不是交付门禁。Stage 3 门禁不过就回滚到保底路线，
  不拿闭环去赌一个没学好的逆头。

## 2. v18 失败的三条教训（本计划逐条修）

### 2.1 逆任务在掩蔽后是病态的，直接回归 I_true 学不出来

- 部署时电流未知，所以逆头输入必须掩蔽：整个历史序列的 I、dI 通道置 0
  后再算 NFL/GRU（否则 `v·i` 等 NFL 特征会把电流泄漏进隐状态）。
  v18 训练做到了这一点，但后果是：在 |v| 很小、G 饱和区（G'→0）、
  v=0 附近（F≈b，与电流无关）时，同一个 (历史, v, F) 对应多个电流，
  MSE 回归只能学出条件均值，inv_mae 卡在 0.464 A（训练 loss_inv 0.095，
  换算 √0.095×1.6≈0.49 A，与验证值自洽，不是评估偶然）。
- 修法：逆 loss 只在“可辨识”样本上算（§5.2 灵敏度加权 + |v| 硬掩蔽），
  并用解析逆解当教师蒸馏（§5.2），而不是只回归带噪声的 I_true。

### 2.2 联合 loss 把共享 GRU 带偏，正向一并变差

- v18：`loss = loss_fwd + 0.1·loss_inv`，全参数同时训。0.1 的权重看着小，
  但逆 loss 初值与正向同量级，且逆任务病态、梯度方向与正向冲突，
  共享 GRU/nfl 特征被带偏后正向 pooled 从 16.27% 恶化到 36.24%。
- 修法：分阶段。先正向训好并冻结（Stage 1），再只训逆头（Stage 2），
  最后才以小学习率、低权重做门禁式联合微调（Stage 3），
  且 Stage 3 正向退化超 1pp 立即回滚。

### 2.3 评估口径不一致：v17 的 inv_mae 0.009 A 不可信，v18 的评估也有掩蔽漏洞

- v17 最优 checkpoint 记录的 inv_mae 0.009 A，是在评估时用**未掩蔽**
  的 u 算 `inverse_predict` 得到的：隐状态里本来就有真电流，逆头近似
  “抄答案”，不能作为部署逆精度的证据。
- v18 的训练用了掩蔽，但 `evaluate()` 里算 inv_mae 时同样没掩蔽
  （`model.inverse_predict(u, ...)` 直接传了含真 I 的 u），所以 0.464 A
  这个数本身也是口径不干净的——只不过它即使在泄漏条件下都没学好，
  更说明逆头有问题。
- 修法（硬性规定，写进 `train_v19.py`，Codex 请重点审这一行）：
  **训练与评估的逆解必须用同一掩蔽协议**：先把整段 u 的第 3、4 通道
  （I、dI）置 0，再算 NFL/GRU/逆头。任何未掩蔽的 inv_mae 不得写入
  metrics、不得用于验收、不得与掩蔽值比较。

### 2.4 附带教训：模型规模不是解药

- v18 把 GRU 从 v17 的 2×16 扩到 64、MLP 48→128、G 24→64，
  参数 20,998→138,512，仍然失败，且已超出 S32 可部署预算
  （v17 估算约 2.3 ms @48 MHz、3 ms 预算内；138k 参数不在此列）。
- 修法：v19 **不扩大骨架**，沿用 v17 的可部署尺寸（§4），
  把算力花在数据对齐和训练协议上，而不是参数量上。

## 3. Stage 0：数据修复（训练开始前必须先过门禁，不过不训）

### 3.1 对齐操作（精确定义）

- 来源：`Raw_Card_Categorized_All`（301 个 M208 原始文件，五类工况）
  经 `process_raw_card_archive.py` 解析得到的 `Parsed_Card_force_wide/`
  （1_SH 204、2_SR 18、3_RHF 9、4_RLF 37、5_ST 33，共 301 个文件）。
  原始解析与原解析结果一律不动。
- 操作（对每个解析后 CSV，采样率 1 kHz）：
  - `force_aligned[t] = force_raw[t+42]`，`current_aligned[t] = current_raw[t+42]`，
    即力、电流两路一起相对位移**前移 42 个采样点（42 ms）**。
    物理含义：记录的 F/I 比位移晚 42 ms，所以 t 时刻的真实 F/I
    就是记录里 t+42 时刻的值。
  - 末尾 42 行丢弃，不做外推/填充（不编造数据）；每文件长度减 42 行。
  - `time`、`rod_length`、`velocity`、`accel`、`temp` 不动；
    `current_dot` 在平移后的电流上重算（梯度 + 原零相位滤波口径）。
  - 温度是缓变量，不参与平移（与 10-22 log 一致）。
- 输出：新目录 `Parsed_Card_force_wide_aligned42/`（与原目录并列），
  附 manifest：每文件原长度、新长度（=原长度−42）、平移点数、
  平移前后力均值（应只差截尾效应，量级 < 数十 N，否则停下来查）。
- 实现：新写 `align_parsed_42ms.py`（只做平移 + 重算 current_dot +
  写 manifest，不碰分段、零点、去偏置逻辑）。该脚本本身也需 Codex
  过目后再跑，跑完先过 §3.2 门禁再进训练。

### 3.2 为什么平移放在“解析后”而不是“原始导出前”

- 解析脚本只做整行裁剪 + 零相位（filtfilt）滤波，零相位滤波不引入
  通道间时延；对已滤波信号做整数点平移是精确操作，不产生相位失真。
- 解析后平移的好处：不重跑分段/零点/去偏置， provenance 清晰，
  出错可一键回退到原解析数据。**请 Codex 核对这一点**：
  若 Codex 认为应在原始列级别平移后再走全套解析（例如担心分段检测
  用了平移前的 I），则以 Codex 的结论为准，改 §3.1，但“F、I 一起移、
  末尾截断不填充、位移不动”三条不变。

### 3.3 对齐验证门禁（四项全过才能开训）

1. SH 相位：解析后 64 个 SH 文件的 F−v 基波相位差不再是恒定 42 ms；
   残余应呈 MTS 模式（数 ms 量级、随频率升高而减小），不是常数。
2. 周期功变号：SH 6.62 Hz 周期功由全负转为全正；
   1.66 / 4.97 Hz 仍为正（对照 10-22 原始值：5 mm / 0.6 A 时
   原始 +3.2 / +3.0 / −3.6 J，平移后 +3.5 / +12.0 / +17.6 J）。
3. 文件清点：301 个文件全在，无一丢失；每文件新长度 = 原长度 − 42。
4. ST 抽查：至少抽 3 个 ST 阶跃文件，目视/互相关确认 F、I 阶跃沿
   与位移运动段对齐，不再系统性晚 42 ms。

### 3.4 训练/验证划分（与 v17/v18 保持可比）

- Holdout 8 个文件 stem 不变（与 v17/v18 完全相同，便于对照）：
  `RLF_RMS10mm_2Hz_r1`、`RLF_RMS15mm_3Hz`、`RLF_RMS10mm_4Hz`、
  `SH_10mm_1.66Hz_1A_r1`、`SH_30mm_1.66Hz_0A_r1`、
  `SR_RMS10mm_1.66Hz_0A`、`RHF_RMS10mm_4Hz`、
  `ST_10mm_Vel0.13_step5_0_1.6A_r1`。
- 剔除清单沿用 `train_v18.py` 的 EXCLUDE_STEMS（含坏文件
  `RLF_RMS10mm_2Hz_r2` 及用户 2026-09-30 确认删除的小幅值高频 RLF）。
- 对照实验（必须做，否则分不清是数据修好了还是架构变好了）：
  把 v17 旧权重（E480 最优）在**对齐后 holdout**上只跑正向评估，
  记为 v17-control。v19 的改进要先与 v17-control 比，再与
  v17 在未对齐数据上的 16.27% 比；两个数口径不同，不得直接画等号。

## 4. 架构 v19：沿用 v17 可部署骨架，只改训练协议

骨架 = `mr_nlcsnn/model_v14.py` 的 `NLCSNN_v14`，尺寸钉死为 v17 配置：

| 部分 | v19 配置 | 说明 |
|---|---|---|
| GRU | 2 层 × 16 | 部署瓶颈，不动 |
| MLP 头（c/s/b/逆头） | 48 | 不动 |
| G 头（Gc/Gs） | 24 | 不动 |
| 摩擦基 σ | [0.5, 1.0, 2.0, 4.0, 8.0] | v17 的 5 基，不回 v18 的 3 基 |
| 参数总量 | 20,998（含逆头） | 上限 21,500；超了就是改错了地方 |
| NFL | `static_nfl_v12`，35 维，σ_nfl=0.1 | v12 磨平版，陡峭特征已修 |
| 正向公式 | F = c·v·Gc(Ie) + (Σ_j s_j·tanh(v/σ_j))·Gs(Ie) + b(h, nfl) | Ie = 1 − \|I\|/1.6；c、s_j 经 softplus + 下限（c_min 2e-3、s_min 5e-3）；Gc、Gs 为 PositiveLinear 单调 MLP，归一化钉死 G(1.6 A)=1 |
| 偏置头 b | 自由（无约束，末层零初始化） | v13 起用户决定：取消 F·v≥0 硬约束，F(0)=b≠0 允许；无源性只审计、不硬约束（见 §6 门禁 G4） |
| 电流滞后 CurrentLag | 可学习，初值 τ 改为 **11 ms** | v18 默认 20 ms 已偏离实测。依据：F、I 一起平移不改变 F−I 相对滞后，执行器对记录电流的滞后实测约 10–12 ms（10-22 分解结论）。请 Codex 核对：τ 是否应在对齐后 ST 数据上重估一次再定初值 |
| 输入 u（6 维） | [rod, v, a, I, dI, temp] | 沿用既有口径：dI 通道在 collate 时置 0（用户要求，dI 引入较大波动）；归一化 v_scale 1000、a_scale 50000、i_scale 1.6、t_ref/t_scale 40 |
| 逆头 inv_head | MLP([h_masked, nfl_masked, v, F_target]) → I_norm ∈ [0,1]（Sigmoid） | 结构沿用 `model_v8._make_inv_head`；关键在掩蔽协议（§2.3），不在头结构 |

逆解两条路线，分工明确：

- **路线 A（解析逆解，部署保底）**：c/s/b 由掩蔽历史固定后，
  f(Ie) 对 Ie 单调，用二分 / 9 点网格求解（v17 MATLAB 已验证路线）。
  解析逆解的精度是正向精度的派生量，不需要单独训。
- **路线 B（神经逆头，增强项）**：只在 Stage 2/3 训，部署时与路线 A
  在同一掩蔽协议下比精度（§6 门禁 G2），输了就不用，只留作研究。

## 5. 训练分阶段（每阶段有出口，上一阶段门禁不过不进下一阶段）

通用协议（沿用用户既定要求，除非本计划明确改动）：

- CPU 训练（`mr-nlcsnn-v3/venv`），AdamW，梯度裁剪 1.0，seed 7，
  文件 batch 12、chunk 12000、AUG_NOISE 0.01；
- 验证节奏按**累计 total_epoch**计：E30 首验、之后每 30 轮
  （注意：`train_v18.py` 默认是 EVAL_START=1 / EVAL_EVERY=20，
  v19 脚本必须显式改成 30/30，否则节奏就错了）；
- 上限 500 累计轮或 holdout pooled NRMSE < 5% 停；看门狗按 total_epoch
  恢复（VM 更换是常态，单 session 轮数不作数）；
- 每验证点画 holdout 对比图并推送 GitHub 方便观察（用户既定要求）；
- 评估跳过前 1000 点（rf=1000，1 s），训练 loss 跳过前 50 点；
  ST 文件 loss 加权 3.0，负力样本加权 1.5（沿用 v18）。

### Stage 1：正向-only（主线，必须先跑完）

- 冻结：无（全参数训正向）；逆头不参与 loss、不更新（或直接不建梯度）。
- Loss：p2p 加权 MSE（与 v18 的 loss_fwd 完全相同）。
- 学习率：AdamW 3e-4，warmup 5 轮，cosine 衰减至 1%，weight_decay 1e-4。
- 初始化：**默认冷启动**。v17 权重是在 42 ms 错位数据上训出来的，
  GRU 动态里可能已内化相位误差，热启动有“先忘掉错位再学对齐”的风险。
  热启动（v17 E480）只作为 Stage 1 成功后的消融对照，不作为主线。
  请 Codex 对“冷启动为主”这一点表态：若 Codex 有把握认为热启动
  更稳且能给出判据（例如前 30 轮 loss 曲线），可改，但须写进记录。
- 出口（§6 门禁 G1）：对齐后 holdout pooled、SH 6.62 Hz 单项、
  v17-control 对照三项齐全，方可进 Stage 2。

### Stage 2：只训逆头，正向骨架冻结

- 冻结：GRU、c/s/b 头、G 头、CurrentLag 全部冻结；只训 inv_head。
- 输入：掩蔽协议（§2.3）下的 [h_masked, nfl_masked, v, F_target]。
- Loss（两项，权重待 Codex 定量，但结构先定）：
  - `L_reg`：掩蔽逆头输出 vs I_true 的 MSE，**只在可辨识样本上算**：
    硬掩蔽 |v| < 10 mm/s 的样本（v≈0 时 F≈b，电流不可辨识）；
    再按灵敏度加权：w = |∂F/∂Ie| 的归一化值（由正向分量解析求导，
    或对 G 做 ±δ 有限差分求导，二者取其一，脚本里只能留一种），
    w < 0.2 的样本不计入 loss，其余按 w 加权。
    请 Codex 核对：10 mm/s、0.2 这两个阈值是否合理，还是应改用
    分位数（如灵敏度最高的 70% 样本）——阈值本身是待审项，不是定论。
  - `L_distill`：掩蔽逆头输出 vs **解析逆解教师**的 MSE。
    教师 = 用冻结正向模型、在掩蔽历史下算出的 c/s/b，
    再对 F_target 做单调 G 二分求解得到的电流（与路线 A 同一求解器，
    教师不带梯度）。教师在低灵敏度区本身也不稳，所以蒸馏同样只在
    可辨识样本上算，权重与 L_reg 相同掩蔽。
  - 两项权重初值建议 L_reg : L_distill = 1 : 1，学习率 1e-4，
    轮数不超过 Stage 1 的 1/3（逆头小，不值得跑满 500 轮）。
- 出口（§6 门禁 G2）：掩蔽 inv_mae、解析逆解对照、灵敏度分层
  （|v|≥50 mm/s 子集）三项齐全。

### Stage 3：门禁式联合微调（可选，默认不开，除非 Stage 2 达标）

- 解冻：全参数，学习率降至 3e-5（Stage 1 的 1/10），cosine 短程。
- Loss：`loss_fwd + λ_inv·L_inv_masked`，λ_inv 初值 **0.02**
  （不是 v18 的 0.1；且 L_inv_masked 必须是 §5.2 的掩蔽+灵敏度加权版，
  不是 v18 的全样本版）。
- **不加 cycle loss 作为训练项**（第一版）。Cycle（用 I_pred 重跑正向
  对 F_target）先只作 Stage 3 的审计指标：若审计发现 cycle 误差
  系统性大于 0.1 A 等效，才在下一版里讨论是否把它加进 loss。
  理由：cycle 需要第二遍 GRU 前向，成本翻倍，且在掩蔽历史下
  “重跑正向”的历史构造本身就有多种写法，没审清之前不进 loss。
- 出口（§6 门禁 G3）：正向退化 ≤1pp 否则回滚 Stage 1 权重，
  逆头结果只保留在实验记录里，不进部署包。

## 6. 验收门禁（全部是数字，不含“感觉变好了”）

| 门禁 | 指标 | 通过线 | 不过怎么办 |
|---|---|---|---|
| G0 数据 | §3.3 四项 | 全过 | 不开训，回 §3 查对齐脚本 |
| G1 正向 | 对齐后 holdout pooled NRMSE；SH 6.62 Hz 单项；v17-control 对照 | pooled ≤17%（v17 在未对齐数据上是 16.27%，口径不同，只作参考不作硬等号）；且 6.62 Hz 单项比 v17-control 好 ≥3pp（相位修好应首先体现在高频） | 停在 Stage 1，查数据/超参，不进联合 |
| G2 逆头 | 掩蔽 inv_mae（全 holdout）；\|v\|≥50 mm/s 子集；解析逆解对照 | 全集 ≤0.15 A；高速子集 ≤0.10 A；且不比解析逆解差 0.05 A 以上 | 只发解析逆解（路线 A），逆头留作研究 |
| G3 联合 | Stage 3 后 pooled vs Stage 1 最优 | 退化 ≤1pp | 回滚 Stage 1 权重 + 路线 A，Stage 3 结果不进部署 |
| G4 无源审计 | 模型在 SH 工况（1.66 / 4.97 / 6.62 Hz）下的周期功符号；另做 Codex 式非无源抽查（小幅值/0 A/室温，2 / 8 / 12 Hz） | 周期功全正；若 6.62 Hz 或高频抽查为负，记为不通过 | 不进闭环；先查 b 分支贡献（Codex 曾定位负功主要来自 b），再决定是否加投影——投影是用户拍板项，本计划不擅自加 |
| G5 S32 可部署 | 参数量、MATLAB 导出、单步耗时 | 参数 20,998（≤21,500）；GRU 2×16 不变；.m 导出后 `clear functions` 再测；MEX 单步逆解在 48 MHz 下重测 ≤3 ms 预算；电流限幅 [0, 1.6] A 在控制器侧（不在训练 loss 里硬加） | 不进部署包，回 §4 查尺寸/导出 |

补充说明（防口径漂移）：

- 所有 pooled NRMSE 均按 v18 的定义：holdout 8 文件 pooled（跳过前 1000 点），
  与 mean/max NRMSE 一起报，不得只报最好单文件。

## 8. 请 Codex 重点审核的 7 个问题（按重要性排序）

1. **掩蔽协议**：§2.3 的“整段 I/dI 置 0 后再算 NFL/GRU”是否足以堵住

## 9. 风险清单（写在前面，训练中出问题先对号入座）

- 对齐后 pooled 反而变差：先看是全频段差还是只差低频；
  全频段差 → 查对齐方向是否反了（前移 vs 后移是最容易反的符号）；
  只差高频 → 查平移点数是否应为 42 以外的整数（如 41/43 的灵敏度）。
- Stage 2 逆头在高速子集达标、全集不达标：属预期内（低速不可辨识），
  按 G2 分层验收，不强行把全集压到 0.10 A。
- Stage 3 回滚：属正常出口，不是失败；回滚后部署包 = Stage 1 + 路线 A。
- VM 更换导致 session 中断：按既有看门狗 + total_epoch 恢复，
  不以单 session 轮数论成败；训练结束（<5% 或 500 轮）或看门狗失败时才汇报，
  自动恢复不打扰用户。
