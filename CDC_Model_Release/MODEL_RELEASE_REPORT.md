## 四、V25「上一拍实测电流」部署要求

### 4.1 数据侧证据（已确认）

| 证据 | 实测值 | 说明 |
|---|---|---|
| ST 阶跃 0→1.6 A 的 10–90% 上升时间 | **10.0 ms**（约 10 点平滑爬升） | 指令通道应为单点矩形跳变 |
| 阶跃峰值 | **1.924 A（过冲）** | 指令不会过冲 |
| 阶跃前残余 | 0.246 A | — |
| 全训练集负电流占比 | **18.31%** | 单极性指令不可能为负 |
| manifest 元数据 | `current_sign_corrected`、`current_shift_samples=42` | 传感器信号做过符号校正与时移对齐 |

**结论：电流列是实测线圈电流（传感器反馈），不是 ECU 指令。**

### 4.2 目标平台要求（**未确认，必须在集成阶段落实**）

- 每个控制周期（10 ms）必须能读到**上一拍实测电流**；
- 若目标 ECU/HIL **只有上一拍命令**，本模型不成立，基准**不得**替换为命令或预测值；
- 逆模型特征需要**双极性**电流传感器（特征槽 21 用的是有符号 `I/1.6`）；
- 上电首拍无同文件上一拍电流：训练与评估中该点被排除，部署上电首拍需由上层定义
  （建议基准置 0，此时输出等于 ΔI）。

## 六、能否进入 C 移植与 HIL

### 6.1 C 语言移植：**可以开始** ✅

已备齐移植必需件：

- 权重（float32，各 11,832 / 11,768 字节）
- 模型定义原件（`model_def.py`，逐字节复制）
- **61 抽头 FIR 系数**（`fir_61tap_40hz.json`，逆模型必需）
- 31 维特征逐项公式 + 时间索引（`feature_spec.json`）
- 归一化 8 参数（`normalization.json`）
- **黄金测试向量**（逐点验收）

移植时的强制要求：
1. 特征顺序**不得重排**
2. 正模型电流必须 `clip(|I|/1.6,0,1)` 并延迟 1 ms
3. 逆模型的两个「上一拍电流」变换**不得合并**
4. 逆模型的 FIR 必须用同一组系数、因果实现、索引 0 对齐
5. GRU 状态与残差基准**逐记录复位**

### 6.2 HIL 集成：**有条件** ⚠️

必须先解决以下两项，否则闭环结果的误差归因不可解释：

| # | 待解决 | 建议 |
|---|---|---|
| 1 | 运动信号 30 ms 群时延不一致（§5.1-1） | 二选一：给正模型加同款滤波器，或给逆模型加延迟补偿。**需单独立项**，本次不修改模型 |
| 2 | 目标 ECU 是否提供上一拍实测电流反馈（§4.2） | 硬件侧确认；若无反馈则本逆模型不成立 |

另需在 HIL 中观测的两个已知弱点：

- **8.05% 的裁剪率**：基准接近 0 时预测为负被截断，可能引起稳态误差；
- **电流变化量总变差为实测的 1.40 倍**：输出比实测更抖。
